# NPU 远程连接与容器管理

首次使用先告知：默认SSH公钥认证，复制 `assets/connection.example.json` 到用户私有目录，每台只填 `ip`、`username`，多台按顺序添加。优先使用当前SSH客户端已有的密钥/ssh-agent或SSH配置；自定义密钥才选填`identity_file`，只记录本机路径，不存密钥内容或密码。不增加容器、目录、卡号等必填字段，无固定PC/WSL路径或默认内网主机。

首次连接或公钥认证失败时，主动按[首次配置免密登录](references/remote-pool.md#首次配置免密登录)引导：识别实际控制端、检查并复用已有公钥、给出适合该用户的服务器端安装命令、验证BatchMode登录、保存私有连接配置。不要只报告认证失败或让用户自行搜索配置方法。用户要求建立连接时可直接提供引导；生成密钥或安装公钥按用户的配置免密授权执行，已有授权不重复询问。私钥不进入聊天、仓库、容器、远程服务器或证据包，自动运行不回退明文密码。

按 [连接与容器流程](references/remote-pool.md) 建立当前任务的执行上下文。凭据由控制端正常SSH认证使用，不回显、不传入命令行、不上传容器或证据包。配置不是独立常驻调度器；代理生成并核查当前平台需要的启动器。

## 职责与交接

1. 按用户名单检查连接、Docker和设备资源，读取容器列表/标签/挂载元数据。只进入用户明确授权或本任务归属确定的容器，不借用他人版本相同的容器。
2. 调用方提供镜像与运行需求；本技能负责创建或连接、独立目录、设备访问和驱动只读挂载。容器名由当前使用者/实例标识、任务、时间戳、随机串生成，检查重名并加owner/task标签，不能使用历史作者前缀。
3. 不安装或升级框架、CANN、驱动，不选择业务后端，不修改模型。构建环境镜像内容由环境技能确定，本技能仅执行其已授权Docker操作。目标环境不匹配则返回缺口，不擅自修复。
4. 为调用方的小型验证或已批准任务，在导入/初始化NPU前选择健康、无进程、利用率0且显存足够的卡；显存需求由任务确定。取得协作锁后复查，整个子进程期间持锁，退出释放。容器不绑定固定卡，单轮eager/compile不换卡。
5. 无空闲卡或连接失败时尝试名单下一主机；全部失败就报告，不无限重试。调用方必须验证新主机环境符合相同需求；已启动的benchmark不自动跨主机重跑或拼接结果。
6. 返回不含凭据的 `execution_context.json`，并按调用方要求传输源码/证据、校验SHA256。后续直接复用该上下文，避免重复索要配置。

上下文记录schema_version、执行方式、主机/容器ID、镜像ID、owner/task、宿主机/容器工作目录、已授权设备范围；实际选卡后追加物理/逻辑映射及锁范围。具体软件版本、Python/CANN激活路径由环境报告补充，不把密码或认证原文写入上下文。

本技能可以单独用于“连接容器”“新建我的验证容器”“检查空闲卡”。环境安装使用 `pytorch214-npu-environment`，模型采集使用 `npu-graph-benchmark-collect`；当前请求没有包含的下一步不自动执行。
