# NPU技能：三类职责，环境按版本独立维护

| 技能目录 | 职责 | 不自动执行 |
| --- | --- | --- |
| `npu-remote-container` | 自动连接宿主机、创建/连接本人任务容器、空闲卡选择、多主机回退、文件传输 | 框架/CANN安装、模型benchmark |
| `pytorch213-npu-environment` | PyTorch2.13 + torch_npu + CANN9.2.0正式版安装/构建与小型验证；此组合须重新验证，不套用9.1.0旧结论 | 模型benchmark、加速比测量 |
| `pytorch214-npu-environment` | PyTorch2.14 + torch_npu + CANN9.2.0正式版的安装/构建、激活、版本与小型设备/图编译/profiler验证 | 模型benchmark、加速比测量 |
| `npu-graph-benchmark-collect` | 融合范围、融合效果、无调试基线的运行、完整产物回收、核验、采集记录及NPU耗时/加速比表格 | SSH配置、容器创建、框架/CANN安装或升级 |

上述四个技能目录分别放入自己的 `$CODEX_HOME/skills/`，未设置时使用当前用户主目录的 `.codex/skills/`。保留目录内相对结构，无需与作者的PC/WSL路径一致。默认分享包包含三类能力、四个独立技能。2.13、2.14环境技能分别维护，未来2.15也新增独立环境技能，不合并成通用版本选择器。2.15尚未建立或验证，不承诺已有支持。

## 用户只需填写的连接配置

仅需要远程连接时，复制 `npu-remote-container/assets/connection.example.json` 到自己的私有目录：

```json
{
  "hosts": [
    {"ip": "主机IP", "username": "用户名", "password": "密码"}
  ]
}
```

填写后只提供文件路径，不在聊天中发送密码，也不将真实文件放入仓库或分享包。多台按顺序添加。容器名、环境路径、卡号自动发现/生成；当前主机无空闲卡时检查下一台，但不借用他人的容器。各技能不重复要求填写这份配置，连接模板只由远程技能维护。

## 可以分三次请求

1. “使用 $npu-remote-container 连接我提供的主机，准备本任务独立容器，暂不安装框架。” 如需新容器而尚未确定镜像，它会先明确镜像需求；不能凭空创建执行环境。
2. “使用 $pytorch214-npu-environment 在这个任务容器准备 PyTorch2.14 + torch_npu + CANN9.2.0正式版，只安装并验证，不跑模型。” 如果先指定了现成环境，可直接检查复用，不能为形式统一重装。
   准备2.13时明确调用 `$pytorch213-npu-environment`，不把2.14技能当作通用版本入口。
3. “使用 $npu-graph-benchmark-collect 在已验证环境收集 DCGAN 训练的融合范围、融合效果和性能基线，先提交方案和命令审核。”

也可以一次授权完整流程，执行代理按这三类职责依次工作，但不因为调用了其中一个就扩大任务范围。benchmark命令仍按约定审核。已有连接/容器、已准备环境直接复用上下文，无需重复运行前两步；离线汇总已有日志可以只使用采集技能。

## 阶段之间交接什么

- 远程技能输出不含凭据的 `execution_context.json`：主机/容器、归属、镜像、工作目录、设备映射与锁范围。
- 环境技能输出 `environment_report.json`：实际PyTorch/torch_npu/CANN版本、解释器、激活路径、来源、验证结果和依赖缺口。原始连接文件不进入报告。
- 采集技能只读复核上述信息，缺环境或模型依赖时返回缺口；只有用户授权环境准备时才转交安装，不在采集技能内部偷偷安装。

## 三类采集

| 阶段 | Debug | Profiler | 回收要求 |
| --- | --- | --- | --- |
| 融合范围 | 开 | 关 | 完整debug目录；核验前后向FX、output_code、ir_pre_fusion与ir_post_fusion |
| 融合效果 | 开 | 开 | 同轮完整debug和profiler原始/解析目录、数据库、时间线 |
| 正式性能基线 | 关 | 关 | 单步耗时、精度、版本与命令证据、加速比表 |

编译缓存默认留远端；分析产物回收后核验SHA256。历史CANN9.1.0数据不改标成9.2.0。debug/profiler轮耗时只作观测，正式加速比使用双关基线，不自动运行GPU或实施优化。

2.13和2.14安装步骤、依赖约束、来源和验证记录独立保留；可以采用一致的文档结构，但不能把版本号替换视为已完成新版本适配。

这些技能是供执行代理使用的工作流与必要工具，不是安装后自动常驻运行的调度服务。耗时汇总脚本只依赖Python3标准库；安装环境仍需要实际NPU驱动、CANN、对应源码与构建工具。

当前采集技能不包含GPU对比、性能原因分析、融合映射和最小复现；后续GPU数据到齐后，再单独建立分析流程或技能。
